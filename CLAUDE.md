# cookyourwebai · how we work here

Public website of CookYourWebAI (www.cookyourwebai.es): React 18 + Vite 5 SPA,
react-router 6, react-helmet-async, Vitest + Testing Library, deployed on Vercel.

**This repository is public.** No personal data, customer data or private
decisions in code, commits or docs.

## 1. TDD, always

Write the test first, watch it fail for the right reason, then make it pass.
Every behaviour that can break gets a test that guards it.

## 2. Conventions

- Commits, pull requests, test names and code comments in **English**. The text
  users read on the website stays in **Spanish** (Spain).
- Conventional Commits, one commit per work unit with its tests. No AI
  attribution in commits.
- Work on `develop` (or a branch from it) and open a PR to `main`. Vercel
  deploys `main`.
- Before each commit: `npx vitest run`, `npx tsc --noEmit -p .` and ESLint on
  the changed files. A test that fails with "Test timed out in 5000ms" in an
  untouched file is machine load: rerun before treating it as a failure.
- Do not run `npm run build` locally: CI builds every push and pull request.

## 3. Check before saying it is done

"It works" or "it is published" only after seeing it: in the browser, with
`curl` against production, or with a test that exercises it.

## 4. Single sources

- Company contact data: `src/lib/company.ts`.
- Site domain: `DOMINIO_POR_DEFECTO` in `src/lib/rutas-publicas.ts`.
- Per-page SEO (title, description, robots): `src/lib/seo.ts`, rendered by
  `src/components/Seo.tsx`.
- `public/robots.txt` and `public/sitemap.xml` are generated by
  `scripts/generar-sitemap.mjs` (runs before every build). Do not edit them by
  hand.

## 5. Against context loss

Adapted from the Reformas Maestras project, where repeated work, reopened
decisions and unreviewed releases all had the same cause: what was decided was
not written in a fixed place. Here that place is `docs/estado.md`.

### At the start of EVERY session (and after every automatic summary)
1. Read `docs/estado.md` entirely. It is the single source of state and
   decisions.
2. `git branch --show-current` and `git log --oneline -5`.
3. Before touching anything, tell the owner in 3 lines: branch, task in
   progress (§0 of `estado.md`) and done criteria. If it does not match the
   request, ask.

### What wins over what
1. Owner decisions in `docs/estado.md` §3.
2. The code and git (what exists today).
3. Dated documents in `docs/` (why something was decided).
4. Memory tools, resume files and conversation summaries **never win**. If they
   contradict 1 or 2, ignore them and say so.

### Decisions
- What the owner decides in the chat **does not exist** until it is in
  `estado.md` §3. Ask "should I record it as a decision?" and write it at once.
- What the owner rejects goes to `estado.md` §3 "Descartado". It is not proposed
  again.
- If a decision and the code disagree, the decision is not reopened: flag it
  once and propose aligning the code.
- When in doubt about something decided: ask, do not infer.

### Tasks
- One task per session, written in `estado.md` §0 with its done criteria.
- "Continúa" means continuing the task in §0, not another one.
- If the owner asks for something new halfway: finish or write down the
  current task in §0 before switching.

### Forbidden without an explicit "yes" from the owner in this session
Merge to `main`, deploy, deleting branches or stashes, publishing claims the
owner has not confirmed.

### When finishing, after a long stretch, or before `/compact`
Update `estado.md`: §0 (done / pending / next step) and whatever changed.
Commit. What is not written down is lost.

### Sub-agents
They start from zero: their brief always says "read `docs/estado.md`" plus the
concrete task and its done criteria.
